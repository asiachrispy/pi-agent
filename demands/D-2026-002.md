# D-2026-002 pi-app 首页「我的任务」列表增加「项目名称」列并统一使用简称

## 意图

- 用户原话（两次略有差异，按最近一次为准）：
  - 「首页中的 我的工作 列表，需要增加一个 项目名称，使用简称，全部列表里面 也要改成简称」
  - 「pi-app首页 我的任务 列表中需要增加一个 项目名称，使用简称，全部列表中也需要使用简称」
- 归属：**pi-app**（Web UI + macOS 桌面），不涉及 `pi` 引擎改动。
- 「项目」在 Pi.app 语义 = 会话的工作目录（cwd），与既有项目选择器（`session-projects.ts` / picker）的概念一致。

## 契约

- 范围：
  - 首页（`WorkbenchHome.tsx`）的「我的工作」区段两种展示态都加「项目名称」列。
  - 展开态（"查看全部"）的 `cwd` 全路径列替换为「项目简称」。
  - 数据层 `ProductHistoryItem` 新增 `projectName: string` 字段，由 `cwd` 派生（`basename(cwd)`）。
- AC 覆盖：
  - AC-1 首页「我的工作」列表存在「项目名称」列（收起态：title/summary 右侧新增列；展开态 grid 在 title 与 updatedAt 之间插入 150px 列）。✔
  - AC-2 该列展示值为项目**简称**（`basename(cwd)`，非全路径、非 ID）。✔
  - AC-3 「全部任务」展开态同样展示为**简称**（原 cwd 全路径列已替换）。✔
  - AC-4 没有「全名 (简称)」重复列（展开态已删 cwd 列，title 加 `title={item.cwd}` 在悬停时显示完整路径作补充）。✔
  - AC-5 列表为空 / cwd 缺失时不报错，显示 fallback `（未设置）`（在 i18n 之外固定占位，避免空值）。✔
  - AC-6 `npx tsc --noEmit`（无输出=通过）、`npx vitest run`（54 files / 255 tests pass）。✔
- 风险：
  - 简称目前 = cwd 末段目录名；如后续要支持"用户自定义项目别名"需要新需求与数据模型变更。
  - 桌面端（macOS）使用同一组件树，自动同步生效，无需单独改动。

  - `pi-app/lib/i18n/messages/zh-CN.ts`：`workbenchHome.projectName = "项目名称"`、`workbenchHistory.projectName = "项目名称"`。
  - `pi-app/lib/i18n/messages/en.ts`：对应英文 `projectName = "Project"`。
  - `pi-app/components/WorkbenchHome.tsx`：收起态在 title/summary 右侧插入项目名（truncate, maxWidth 160px）；展开态把原 `item.cwd` 列替换为 `item.projectName`（150px grid 列，`grid-cols-[minmax(0,1fr)_150px_120px_auto]` 4 列：title/projectName/updatedAt/details）；两态均加 `title={item.cwd}` 悬停显示完整路径。
